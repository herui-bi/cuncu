# 惠衢保 7.0 二期功能 — 测试用例清单

- 需求来源：`docs/testcases/【投保分销】惠衢保7.0二期功能.docx`（含一期基础信息：`【投保分销】惠衢保7.0一期.docx`）
- 项目/产品：惠衢保 2027（项目号 CITY000110-1）；产品 LH677 基础版 100 元、LH678 升级版 200 元、LH679 尊享版 300 元（未成年人基础版 80 元）
- 被测模块：订单升级（C 端 H5 订单列表 / 订单详情 / 保障方案升级页 / 收银台）、支付、签约、代扣、续期、历史链接映射、荷叶对接
- 运行环境：`config/environments/huiqubao/test.yaml` → `https://test-insure.meditrustbroker.com/hqb7h5/?code=hqb7_test#/index`（测试环境保费为 0.01/0.02/0.03 元）
- 数据文件：`data/huiqubao/caseData.xlsx` → `upgrade` 工作表
- 页面对象：`pages/huiqubao/order_upgrade_page.py`
- 脚本：`testcases/huiqubao/test_order_upgrade.py`
- 编号规则：`hqb_001` 起递增，全项目唯一
- 公共前置：H5 已登录（`?code=hqb7_test` 授信）；账号下存在对应状态的惠衢保 2027 订单
- 公共测试数据约定：缴费人使用实名身份池中的真实身份；升级页金额=所选被保人「所选版本单人保费」之和；测试环境单人保费 0.01 元、升级版 0.02 元、尊享版 0.03 元（以页面实际为准，Excel 中参数化）

### hqb_001 基础版单人已支付订单-订单列表展示「升级保障」入口

- 前置条件：公共前置；账号下存在基础版（LH677）已支付、1 位被保人的订单
- 操作步骤：
  1. 进入「我的订单」
  2. 找到基础版已支付订单卡片
- 测试数据：订单版本 基础版，被保人数 1，订单状态 已支付

  1. 订单卡片展示「升级保障」与「查看详情」两个按钮

### hqb_043 基础版升级-原订单退款后重新下单并按原支付方式支付

- 前置条件：公共前置；基础版已支付订单（微信支付）；在升级页选择升级版并勾选协议
- 操作步骤：
  1. 原订单先申请退款，等待两张原保单状态变为已退款（refundedRevoked）
  2. 点击「一键升级」，在「请确认是否需要升级保障？」弹窗点确认，生成待支付升级订单
  3. 进入收银台，确认默认选中「微信支付」
  4. 勾选「我已阅读并同意《支付协议》」后点击「支付」，使用 mock 的微信支付回调返回成功
- 测试数据：订单 E826111309530292800023（LH677 医保全款已支付 0.01 元；微信全款已支付订单已消耗），升级方案 升级版
- 预期结果：
  1. 退款接口返回成功，轮询订单详情后原保单全部为已退款状态
  2. 升级下单接口返回真实升级订单号并跳转收银台 `#/pay?orderNo=...`，展示支付倒计时与订单信息，支付方式含个账支付（置灰）、微信支付、支付宝
  3. 个账不可用时默认选中「微信支付」（原订单支付方式）
  4. mock 微信支付回调 `get_brand_wcpay_request:ok` 后跳转支付成功页 `#/paySuccess?orderNo=...`，展示「支付成功」
- 优先级：P0；可自动化：是；`test_type=payment`；`order_state=base_paid`
- 数据说明：本用例会真实退款原订单（不可逆）并真实生成待支付升级订单，仅支付环节的微信 H5 支付链接与 JSAPI 回调以 mock 返回成功、不产生真实扣款；升级下单接口偶发网关 504 时，自动回查数据库升级历史表获取真实升级订单号。Excel 当前标记 `enabled=N`：账号下微信全款已支付订单已消耗（现有微信订单均为部分退款），且实测医保订单退款接口返回「医保账户异常，退款失败」，mock 支付无法生成已支付订单，补充新的微信全款已支付订单后恢复

### hqb_044 升级版升级-原订单退款后重新下单并按原支付方式（医保）支付

- 前置条件：公共前置；升级版已支付订单（医保支付）；在升级页选择尊享版并勾选协议
- 操作步骤：
  1. 原订单先申请退款，等待原保单状态变为已退款（refundedRevoked）
  2. 点击「一键升级」，在「请确认是否需要升级保障？」弹窗点确认，生成待支付升级订单
  3. 进入收银台，确认默认选中「医保支付」（原订单支付方式）
  4. 勾选支付协议后点击「支付」，在「本次投保将使用您的医保账户余额支付。」确认弹窗点确认
- 测试数据：订单 E826111216054339000003（吴昭照，升级版 LH678，医保支付 0.02 元；已消耗，等待补充新医保已支付订单），升级方案 尊享版
- 预期结果：
  1. 退款接口返回成功，轮询订单详情后原保单为已退款状态

  3. 收银台默认选中「个账支付」（医保渠道，原订单 payMethod=ybpay）
  4. mock 医保支付接口 `GET /core/order/ybPay` 返回成功后跳转 `#/partSuccess?orderNo=...` 支付处理页
- 优先级：P0；可自动化：是；`test_type=payment`；`order_state=upgrade_paid`
- 数据说明：本用例会真实退款原订单（不可逆）并真实生成待支付升级订单，仅医保支付接口 ybPay 以 mock 返回成功、不产生真实医保账户扣款。医保渠道在收银台展示为「个账支付」（底层 payMethod=ybpay）。实测已验证：升级版医保订单升级时原保单退款成功、尊享版待支付订单真实生成、收银台默认选中医保渠道；Excel 当前标记 `enabled=N`：唯一升级版医保已支付订单已被本用例消耗，补充新订单后复跑完整支付链路

## 三、自动化可行性结论

- 可自动化（UI）：`hqb_001`~`hqb_018`、`hqb_041`~`hqb_047`，共 25 条，依赖账号下具备对应状态订单；数据需求与获取方式见独立文档 [huiqubao7_data_prep.md](huiqubao7_data_prep.md)。
- 不可自动化（本期）：`hqb_019`~`hqb_040`，共 22 条，涉及医保资质不通过构造、真实支付/退款、签约代扣后台、续期/映射/对接与埋点，统一标注人工/接口验证，报告中原样列出。
- 环境依赖：测试环境入口 `hqb7h5/?code=hqb7_test`；测试库订单姓名/手机号加密存储，无法直接反查登录账号，升级用例所需的「基础版已支付订单」需通过 H5 投保+支付链路自建，或由业务方提供可登录测试账号。
