# 东营惠民保 2027 投保对接 — 测试用例清单

- 需求来源：`docs/testcases/东营惠民保2027投保对接 (1).docx`
- 被测模块：个单投保（H5）
- 运行环境：`config/environments/dongying/test.yaml`（东营 H5 测试环境）
- 数据文件：`data/dongying/caseData.xlsx` → `policy` 工作表
- 页面对象：`pages/dongying/individual_policy_page.py`
- 脚本：`testcases/dongying/test_individual_policy.py`
- 编号规则：`policy_001` 起递增，全项目唯一
- 公共前置：进入投保页 → 点击缴费人姓名关闭投保须知 → 填写缴费人（钟诚 / 420102198401140032 / 19370919218）→ 获取并输入短信验证码 888888 → 确认快速注册
- 公共测试数据约定：被保人关系取「子女」，出生日期均晚于缴费人 1984-01-14；被保人不做外部参保资格校验，证件号按出生日期生成（记录告警），缴费人使用实名身份池中的真实身份

### policy_012 完整下单-强制阅读协议、签字临摹与订单创建

- 前置条件：公共前置；会产生真实订单
- 操作步骤：
  1. 新增 1 名成年被保人，默认「升级版」
  2. 选择支付方式「微信支付」
  3. 勾选协议复选框，按序逐份将协议滑动到底部并点击「我已阅读并确认」
  4. 点击「立即投保」，签字面板逐字核对并临摹缴费人中文名，点击「完成签名」
  5. 进入订单列表 → 订单详情读取订单号
  6. 按订单号尾号定位分表，查询 `share_code`
- 测试数据：成年人C，出生日期 1990-05-20，关系 子女；支付方式 微信支付；期望 share_code 留空（只回显）
- 预期结果：
  1. 每份协议未滑到底部时确认按钮不可点击，滑到底部后可点击
  2. 签字面板每个字与投保人姓名逐字一致
  3. 下单成功，订单详情页可读取到订单号（E 开头）
  4. 分表查询到该订单，`share_code` 回显到报告
- 优先级：P0；可自动化：是（下单用例，`-k` 过滤时避免重复执行）

## 三、用例完整性校验结论

| 检查项 | 结论 |
|---|---|
| 用例编号唯一 | 通过（policy_001 ~ policy_012，policy_101 ~ policy_112） |
| 必填项（编号/标题/步骤/预期） | 通过 |
| 测试数据可落地 Excel | 通过（`data/dongying/caseData.xlsx` → `policy`） |
| 数据自相矛盾 | 无：被保人均为「子女」且出生日期晚于缴费人 1984-01-14 |
| 预期可断言 | 通过：监护人提示、保障计划集合、默认版本、浮层文本（包含匹配）、保费合计、订单号 |
| 环境依赖 | 通过：`config/environments/dongying/test.yaml` 提供东营 H5 入口，默认项目即东营 |
| 实名身份 | 缴费人 钟诚（实名池）；被保人无需外部参保资格校验，证件号按出生日期生成并记录告警 |
| 身份池缺口 | 池中仅 1 个真实身份，仅够缴费人使用；未成年人边界用例必须使用生成号（不触发实名） |
| 浮层文本稳定性 | 需求文档中的「即将满足/恭喜」前缀可能与历史 DOM 不一致，断言改为包含匹配 |
